A curated shortlist selected for hackathon speed, documentation quality, and a credible path beyond the demo.

## Selection guidance

- Prefer one primary tool per concern. Do not combine multiple databases, authentication systems, or deployment platforms without a clear requirement.
- Confirm pricing, regional availability, quotas, data terms, and event-specific credits before committing.
- Use test or sandbox modes for payments, email, messaging, and destructive integrations.
- Record every external dependency in the project README, including fallback behavior.

## Hackathon default

Choose the option your team already understands unless a sponsor challenge requires something else. Familiar tools usually outperform theoretically superior tools during a time-limited build.
