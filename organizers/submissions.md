# Submission Operations

## Submission contract

Publish the exact deadline with timezone, required fields, eligibility rules, repository visibility requirements, video limits, licensing expectations, sponsor-challenge fields, judging criteria, and late-submission policy.

## System readiness

Test account creation, draft saving, uploads, repository links, video playback, team membership, timestamps, exports, judge access, and recovery from partial failure. Run the full flow using a participant account and a judge account.

## Required evidence

A strong submission includes the problem, target user, working demo, architecture summary, repository, setup instructions, team contributions, external resources, limitations, safety considerations, and license.

## Deadline operations

Announce reminders at consistent intervals. Freeze rule changes before the deadline. Log platform incidents and apply any extension consistently to all eligible teams.

## Validation

Automate simple checks but preserve human review for edge cases. Flag missing links, inaccessible videos, empty repositories, eligibility conflicts, duplicate submissions, and sponsor-challenge mismatches.

## Audit and retention

Keep an immutable export of submitted data and timestamps. Limit access, define retention, and provide a correction process for non-scoring metadata without silently altering judged evidence.
