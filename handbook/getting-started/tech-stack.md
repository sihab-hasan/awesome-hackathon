# Choosing a Technology Stack

Use the least complex stack that supports the core workflow.

## Decision order

1. Team familiarity.
2. Event or sponsor requirements.
3. Data sensitivity and legal constraints.
4. Deployment speed.
5. Availability of documentation and examples.
6. Reliability under demo conditions.
7. A path to continue after the event.

Use [STACK-SELECTOR.md](../reference/stack-selector.md) for a full decision matrix. Do not add a second framework, database, or cloud provider unless it solves a documented problem.
