# Responsible Innovation

A solution can be technically impressive and still create avoidable harm.

## Review questions

- Who benefits, who bears risk, and who is excluded?
- What happens when the system is wrong?
- Can a user contest, correct, or reverse an outcome?
- Does the interface overstate confidence or capability?
- Could the project enable harassment, discrimination, surveillance, manipulation, unsafe automation, or unauthorized access?
- Is a less invasive design sufficient?

Document the most important limitation and one concrete mitigation in the pitch. Avoid claims that the prototype has been clinically, legally, financially, or operationally validated when it has not.
