# Team Roles

Roles describe ownership, not job titles. One person may hold several roles, but every high-risk decision needs one accountable owner.

| Role | Accountable for |
| --- | --- |
| Product owner | Target user, scope, acceptance criteria, and demo narrative |
| Technical lead | Architecture, integration sequence, and engineering trade-offs |
| Experience owner | User flow, accessibility, copy, and visual consistency |
| Data or AI owner | Data provenance, evaluation, model behavior, and limitations |
| Reliability owner | Deployment, logs, secrets, fallback, and rollback |
| Submission owner | Rule compliance, evidence, video, repository, and deadline |

## Decision discipline

Use a simple RACI record for the API choice, data source, deployment, external actions, demo flow, and submission. Resolve disagreements by returning to the target outcome and remaining time.

## Handoffs

Every subsystem should have a short run command, test command, known failure, and owner. Avoid knowledge that exists only in one person’s terminal history.
