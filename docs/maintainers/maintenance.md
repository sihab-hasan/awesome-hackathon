# Maintenance Policy

## Objectives

The repository is maintained as a dependable, low-noise field guide rather than an unbounded link dump. Maintenance prioritizes accuracy, practical hackathon value, official or primary sources, and reproducible generated views.

## Cadence

- External links are checked weekly by automation.
- Catalog entries should be editorially reviewed at least every 180 days.
- Dependency and GitHub Actions updates are reviewed weekly.
- Documentation, schema, and generator changes require repository validation.
- A tagged release should be created after material catalog, governance, or tooling changes.

## Resource lifecycle

- `active`: suitable for normal recommendation.
- `deprecated`: still documented for migration context but not recommended for new projects.
- `archived`: retained only for historical or attribution purposes.

An entry may be removed when its primary URL disappears, the project becomes unsafe or misleading, maintenance ceases without a stable archive, its hackathon use case is unclear, or a materially better canonical source replaces it.

## Review responsibilities

Maintainers review source quality, affiliation disclosures, duplicate coverage, cost claims, security implications, and whether generated pages remain synchronized. Automated checks support editorial review but do not replace it.

See [Curation Policy](curation.md), [Governance](governance.md), and [Release Process](releasing.md).
