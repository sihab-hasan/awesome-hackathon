# Presentation Checklist

Use this list as a release gate. Record unresolved items as explicit risks rather than silently skipping them.

- [ ] Opening states the user and problem.
- [ ] Demo follows one coherent outcome.
- [ ] Architecture explanation matches implementation.
- [ ] Claims are supported by visible evidence.
- [ ] Limitations and simulated parts disclosed.
- [ ] Every presenter knows the transition points.
- [ ] Timebox rehearsed with questions.
- [ ] Backup video and screenshots available.

## Sign-off

Record the owner, timestamp, tested artifact, and any accepted exception.
